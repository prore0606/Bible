# 광고(AdMob) 설정과 출시 전 교체 순서

작성일 2026-10-18 · T13 · 규칙은 `docs/spec.md` 9장, 코드는 `src/lib/ads.ts`·`admobProvider.ts`·`adIds.ts`

## 지금 상태 (개발·내부 테스트)

- 앱(안드로이드)에서는 **Google 공식 테스트 광고**만 나옵니다. 실제 광고 단위 ID는 코드에 없습니다.
- 테스트 앱 ID(`ca-app-pub-3940256099942544~3347511713`)가 `android/app/src/main/res/values/strings.xml`의 `admob_app_id`에 들어 있습니다. 이 값이 없으면 앱이 시작하자마자 종료됩니다.
- 브라우저(웹 개발 모드)에서는 SDK 대신 "광고 자리" 화면을 1초 보여 줍니다.
- 개발 중에는 실제 광고를 누르지 않습니다 (계정 정지 위험). 테스트 광고는 눌러도 됩니다.

## 광고가 나오는 곳 (절대 규칙)

| 종류 | 위치 | 조건 |
| --- | --- | --- |
| 전면 | 미션 완료 직후, 완료 시트 전 | 하루 최대 1번. `/pray`에서 미리 불러오고 3초 안에 준비 안 되면 건너뜀 |
| 보상형 | 기록 화면의 되살리기 | 끝까지 봐서 보상이 지급돼야 되살아남. 중간에 닫거나 불러오지 못하면 되살아나지 않음 |
| 배너 | 기록 화면 하단(탭바 위) | 기록 화면에 있는 동안만. 광고가 안 오면 자리를 접음 |

읽기·기도 중간에는 광고가 없습니다. 광고 때문에 미션 완료가 막히지 않습니다(실패·오프라인이면 광고 없이 진행).

## 출시 전에 할 일 (사용자 준비물 + 교체)

1. **AdMob 계정을 만들고 앱을 등록**합니다 (패키지명 `kr.co.prore.malsseumsup`). 앱 ID(`ca-app-pub-…~…`)를 받습니다.
2. **광고 단위 3개**를 만듭니다: 전면 · 보상형 · 배너. 광고 단위 ID(`ca-app-pub-…/…`) 3개를 받습니다.
3. **광고 콘텐츠 등급**을 가장 낮게(전체 이용가) 두고 도박·데이트·주류 등 민감한 카테고리를 차단합니다.
4. 출시 빌드에서만 실제 ID로 바꿉니다.
   - `.env.example`을 `.env.local`로 복사해 `NEXT_PUBLIC_ADMOB_MODE=production`과 광고 단위 ID 3개를 채웁니다. 하나라도 빠지거나 형식이 틀리면 테스트 광고로 돌아갑니다(실수로 빈 ID가 나가지 않음).
   - `strings.xml`의 `admob_app_id`를 실제 앱 ID로 바꿉니다. (이 값은 환경 변수가 아니라 안드로이드 설정이라 직접 바꿉니다.)
   - `npm run build` → `npx cap sync android` → 릴리스 빌드.
5. **app-ads.txt**: 스토어에 등록하는 개발자 웹사이트(prore.co.kr) 루트에 AdMob이 안내하는 `app-ads.txt`를 올립니다.
6. **동의(UMP)**: 코드는 이미 동의 정보를 확인하고, 동의가 필요한 지역(유럽·영국 등)에서만 동의 화면을 띄웁니다. AdMob 콘솔의 "개인 정보 보호 및 메시지"에서 유럽 규정 메시지를 만들어 두어야 실제로 화면이 나옵니다. 배포 국가에 유럽·영국을 넣지 않으면 신경 쓰지 않아도 됩니다.
7. 실제 광고 ID로 바꾼 빌드는 **개발 중에 직접 눌러 보지 않습니다**. 확인이 필요하면 AdMob 테스트 기기를 등록합니다.

## 폰에서 확인할 것 (T13 확인 기준)

- [ ] 전면 광고가 하루 1번만 (날짜를 바꿔 다음 날 다시 확인)
- [ ] 보상형: 끝까지 보면 연속이 되살아나고, 중간에 닫으면 되살아나지 않음
- [ ] 배너: 기록 화면에서만 보이고 탭바를 가리지 않음 (배너 위치 `margin`은 탭바 높이 62dp 기준이라 기기에서 어긋나면 `src/lib/ads.ts`의 `TAB_BAR_HEIGHT` 조정)
- [ ] 비행기 모드·광고 불러오기 실패에도 미션 완료가 정상, 기록 화면 하단에 빈 공간이 없음
