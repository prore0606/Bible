## 4. 서명 키 (keystore) — 잃어버리면 업데이트를 못 합니다

1. Android Studio 또는 `keytool`로 **업로드 키**를 만듭니다. 파일 확장자 `.jks`/`.keystore`.
2. 키 파일과 비밀번호를 **서로 다른 안전한 곳 두 군데 이상**(예: 암호 관리자 + 외장 저장소)에 보관합니다.
3. 키 파일과 비밀번호는 **git에 올리지 않습니다** (`.gitignore`에 `*.jks`, `*.keystore`가 들어 있음).
4. Play Console에서는 "Play 앱 서명"을 사용하는 것을 권장합니다. 그러면 업로드 키를 잃어도 Google에 재설정을 요청할 수 있습니다. (정책은 등록할 때 Play Console 안내를 확인)

## 5. 버전 규칙

| 값 | 위치 | 규칙 |
| --- | --- | --- |
| `versionName` (사용자에게 보이는 버전) | `package.json`의 `version`(앱 정보 화면에 표시)과 `android/app/build.gradle`의 `versionName`을 **같은 값**으로 | 첫 출시 `1.0.0`. 기능 추가 `1.1.0`, 고침 `1.0.1` |
| `versionCode` (정수) | `android/app/build.gradle` | **업로드할 때마다 반드시 1씩 올림** (같거나 낮으면 업로드 거부) |

## 6. 출시 절차

1. 폰 확인(1항) 통과, 문서 칸 채우기(privacy-policy.md `[ ]`, links.ts)
2. 실제 광고 ID로 교체한 릴리스 빌드(AAB) 만들기: `npm run build` → `npx cap sync android` → Android Studio에서 서명된 AAB 생성
3. Play Console **내부 테스트**에 업로드 → 지인 몇 명이 설치·실행 → 피드백 반영
4. 스토어 등록 정보·설문·개인정보처리방침 URL 입력
5. 프로덕션 심사 제출
6. 출시 후: 크래시/ANR, 광고 수익, 리뷰 모니터링
