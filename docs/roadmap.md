- **T3과 T4는 서로 독립**이라 번갈아 진행할 수 있습니다. 다만 T5(홈의 초록 배너가 구절을 보여줌)부터는 T3이 필요합니다.

- **브라우저에서 앱을 먼저 완성**(T3~T10)하고, 그다음 폰에서 확인(T11~T13)합니다. 폰 환경 문제가 화면 개발을 막지 않게 하기 위해서입니다.

## 3. 작업 방식 (모든 T에 공통)

### 3.1 진행 규칙
1. **한 번에 한 T만** 합니다. 끝나면 확인 기준을 직접 확인한 뒤 다음으로 넘어갑니다.
2. **브랜치는 T마다 새로 만듭니다.** 예: `feature/t3-bible-data`. `main`에서 직접 작업하지 않습니다.
3. **커밋은 의미 단위로 나눠서** 하고, T가 끝나면 GitHub에 푸시합니다. 합치기(main 병합)는 사용자가 확인한 뒤에 합니다.
4. `spec.md`에 없는 기능은 임의로 추가하지 않습니다. 애매하면 먼저 묻습니다.
5. 결정이 바뀌면 `spec.md`/`CLAUDE.md`와 이 문서 7장을 같이 고칩니다.

### 3.2 "끝났다"의 기준 (모든 T가 통과해야 함)
- `npm test` 전부 통과
- `npx tsc --noEmit` 오류 없음
- `npm run lint` 경고·오류 없음
- `npm run build`(정적 export) 성공
- 화면이 있는 T는 **브라우저에서 직접 열어 확인**(Playwright로 흐름을 따라가고, 사람이 눈으로도 확인)

### 3.3 테스트를 쓰는 방식
| 대상 | 방법 | 위치 |
| --- | --- | --- |
| 규칙·계산 (순수 함수) | Vitest 단위 테스트 | `tests/lib/` |
| SQL·저장 흐름 | Node 내장 SQLite로 진짜 엔진에서 실행 | `tests/db/` |
| 전역 상태 | 시계(`now`)를 바꿔 끼워 자정 넘김 등 재현 | `tests/app/` |
| 화면 흐름 | Playwright로 클릭·입력·새로고침 | 확인용(필요하면 `tests/e2e/`) |
| 폰 동작 | 실기기 수동 체크리스트 | spec 11장 |

테스트는 **한국 시간대(Asia/Seoul)**로 실행되어, 날짜가 하루 어긋나는 버그를 실제로 잡습니다.

### 3.4 화면 만들 때 지킬 것 (공통)
- 색·모서리·그림자는 **디자인 토큰만** 씁니다(`bg-blue`, `text-grape` 등). 색상값 직접 입력 금지.
- 화면 폭은 최대 480px, 좌우 여백 16px, 카드 사이 8px.
- 폰의 안전 영역(노치·하단 바)을 `env(safe-area-inset-*)`로 처리합니다.
- DB·플러그인·`window`는 **클라이언트 컴포넌트의 `useEffect` 안에서만** 부릅니다(정적 export 때 서버에서 실행되지 않게).
- 화면은 `store`의 상태와 액션만 쓰고, SQL이나 규칙을 직접 건드리지 않습니다.
- 모든 버튼·입력에 접근성 이름(`aria-label`)을 답니다.

### T3. 성경 본문 데이터 (`feature/t3-bible-data`) — ✅ 완료

> **결과 요약** (자세한 내용은 [`docs/bible-data.md`](bible-data.md))
> - 원본: `crizin/bible-db` (커밋 `4bcb50b`). 개역한글은 holybible 수집본을 기본으로 쓰고, 대한성서공회 수집본과 대조해 뜻이 달라지는 3곳만 교정. 대한성서공회 수집본은 시편 92편이 없고 번호가 비어 단독 사용 불가
> - 66권 × 2개 언어, 개역한글 31,101절 / KJV 31,102절, 약 8.7 MB(압축 약 2.5 MB)
> - **절 번호는 KJV 기준** → 약 100개 장에서 인쇄된 개역한글과 번호가 다름 (결정 D-17). 앱 정보에 안내 문구 필요
> - 출시 전 검수: 표기가 갈리는 10곳, 저작권 근거 캡처, 영국 배포 여부(KJV)
> - 아래는 계획 당시 내용이며, 실제 구현은 `scripts/build-bible.mjs`, `src/lib/bible.ts`, `tests/lib/bible.test.ts`

**목표**: 개역한글·KJV 66권을 앱이 읽을 수 있는 JSON으로 준비하고, 읽는 코드(`bible.ts`)를 만듭니다.

**만들 것**
| 파일 | 내용 |
| --- | --- |
| `public/bible/ko/{BOOK}.json` ×66 | 개역한글. 구조 `{ "code", "name", "chapters": string[][] }` |
| `public/bible/en/{BOOK}.json` ×66 | KJV, 같은 구조 |
| `scripts/build-bible.mjs` | 원본 데이터를 위 구조로 변환하는 스크립트 (다시 만들 수 있게 보관) |
| `src/lib/bible.ts` | `loadBook(lang, code)`, `getChapter(lang, ref)`, 책 단위 메모리 캐시 |
| `tests/lib/bible.test.ts` | 구조·장 수·샘플 구절 검증 |

**구현 포인트**
1. **원본 선택** — 공개된 개역한글/KJV 데이터를 찾습니다. 후보를 3개 정도 비교해서 아래 조건을 만족하는 것을 고릅니다.
   - 라이선스·출처를 확인할 수 있을 것 (대한성서공회 사이트를 자동으로 긁어오지 않음)
   - **진짜 개역한글인지** 확인: 창세기 1:3이 "하나님이 **가라사대** 빛이 있으라"이면 개역한글, "이르시되"이면 개역개정(저작권 살아 있음)
2. **변환 스크립트** — 원본 형식이 무엇이든 `chapters[장-1][절-1]`로 맞춥니다. 절이 비는 곳(원본에 없는 절)은 빈 문자열로 두지 않고 알려줍니다.
3. **검증** — 변환 직후 자동으로 확인합니다.
   - 책 66권 모두 존재, 장 수 합계 1,189장이 `books.ts`와 일치
   - 한국어·영어 **장별 절 수 비교표**를 출력 (번역본 간 절 번호 차이가 있는 곳 확인)
   - 빈 문자열·앞뒤 공백·깨진 문자 검사
4. **`bible.ts`** — 앱 안에서는 `fetch('/bible/ko/GEN.json')`으로 책 한 권씩 불러오고 메모리에 캐시합니다. 한국어·영어를 함께 보여줄 때는 **절 번호를 기준으로** 짝을 맞춥니다(배열 위치가 아님).
5. 개발 모드에서 앱 시작 때 `books.ts`와 JSON의 장 수가 맞는지 검사합니다(spec 6장).

**위험/결정**
| 항목 | 내용 |

**`/bible` (자유 읽기)**: 책·장 고르기 → T6의 본문 컴포넌트를 그대로 재사용. 미션 진도와 무관하고 구절 저장은 가능. 책·장은 **쿼리스트링**(`?book=PSA&chapter=23`)으로 받습니다(1,189개 정적 페이지를 만들지 않기 위해).

**구현 포인트**
- **테마 깜빡임 방지**: 테마 설정은 SQLite에서 비동기로 읽혀서, 그대로 두면 켜질 때 밝은 화면이 번쩍입니다. 마지막으로 쓴 테마를 `localStorage`에도 복사해 두고 첫 화면 그릴 때 먼저 적용합니다(Next.js 문서 `preventing-flash-before-hydration` 참고).
- **다크 색 확정(결정 D-05)**: spec은 5개 색(배경·카드·blue·green·butter)만 정했고 ink·gray·line·형광펜 등은 현재 임시 값입니다. 이 T에서 화면과 함께 확정하고 `spec.md` 3장에 반영합니다.
- 설정을 바꾸면 즉시 `store.updateSettings()`로 저장하고 화면에 반영.

**확인 기준** (spec T10)
- [ ] 읽는 곳을 바꾸면 다음 미션부터 적용 (오늘 미션은 그대로)
- [ ] 한·영 동시 표시, 글자 크기 3단계, 다크 테마가 모든 화면에서 읽을 수 있음
- [ ] 자유 읽기로 아무 책·장을 읽을 수 있고 미션 진도는 그대로
- [ ] 새로고침해도 테마가 깜빡이지 않음

> ✅ **여기까지가 "브라우저에서 앱 완성" 지점**입니다. 이 시점에서 사용자 확인을 한 번 받고 T11로 넘어갑니다.

### T12. 알림 (`feature/t12-notifications`)

**목표**: 하루 1번, 사용자가 고른 시간에, 오늘 미션을 안 했을 때만 알림.

**만들 것**
| 파일 | 내용 |
| --- | --- |
| `src/lib/notify.ts` | **계획 함수** `planNotifications(...)`(순수) — 입력: 현재 시각, 알림 설정, 오늘 완료 여부, 성장일, 진도 / 출력: 앞으로 7일치 `{id, 시각, 제목, 본문}` |
| `src/lib/notifyScheduler.ts` | `@capacitor/local-notifications`로 기존 예약을 모두 지우고 위 계획대로 다시 예약 |
| 권한 흐름 | `/setup/alarm`의 "이대로 시작할게요" → 권한 요청 → 허용이면 예약, 거부면 알림 끔. 설정에서 다시 켤 때 재요청, 시스템에서 막혀 있으면 기기 설정으로 안내 |

**구현 포인트**
1. **재예약 시점**: 앱을 열 때, 미션을 완료할 때, 알림 설정을 바꿀 때마다 전부 지우고 다시 예약.
2. **오늘 건너뛰기**: 오늘 미션이 이미 완료됐으면 오늘 알림은 빼고 내일부터.
3. **문구**(제목은 항상 "성경-말씀숲", 하루 1개를 넘지 않음):
   - 기본: "오늘의 1장이 기다리고 있어요 · {책} {장}장" / "알알이가 물을 기다려요. 오늘 1장 읽어 볼까요?" (번갈아)
   - 이정표: "오늘 1장을 읽으면 {이정표 문구}"
   - 어제 놓침: "어제는 쉬었어요. 오늘 다시 함께 시작해요" — 죄책감 없는 말투
4. **미래 날짜 문구의 한계(주의)**: 7일치를 미리 예약하므로 "어제 놓침" 문구는 **예약 시점에 확정되는 첫날에만** 쓸 수 있고, 이정표 문구도 "매일 완료한다"는 가정으로 계산합니다. 어긋나는 날은 기본 문구로 둡니다. (결정 D-11)
5. **정확한 시각**: Android 12 이상에서 정확한 시각의 알람은 별도 권한이 필요하고 Google Play 정책 제한이 있습니다. **기본은 권한을 요청하지 않는 방식**(몇 분 늦을 수 있음)으로 하고, 구현 때 공식 문서로 확인합니다. Android 13 이상은 알림 권한(`POST_NOTIFICATIONS`)이 필요합니다.
6. 알림을 누르면 앱이 열리며 `/home`으로 이동.
7. 앱 시작 시 알림 설정이 꺼져 있거나 권한이 없으면 예약하지 않음.

**테스트**: `planNotifications` 단위 테스트(7일치 개수, 오늘 완료 시 제외, 12→24시간 변환, 문구 선택, 알림 ID 중복 없음, 자정 경계).

**확인 기준** (spec T12)
- [ ] 알림 시간을 2분 뒤로 맞추면 알림이 옴
- [ ] 미션을 끝낸 날은 오늘 알림이 오지 않음
- [ ] 권한 거부 후 설정에서 다시 켜기 동작
- [ ] 알림을 누르면 홈으로

### T13. 광고 AdMob (`feature/t13-ads`)

**목표**: 전면·보상형·배너를 **테스트 광고 ID로** 붙입니다.

**사용자 준비물**: AdMob 계정, 앱 등록(앱 ID), 광고 단위 3개(전면·보상형·배너) — 실제 ID는 출시 직전에만 사용.

**만들 것**
- `@capacitor-community/admob` 설치, `AndroidManifest.xml`에 **AdMob 앱 ID 등록**(없으면 앱이 시작하자마자 죽음 — 개발 중에는 Google 공식 테스트 앱 ID 사용)
- `src/lib/ads.ts`의 `AdProvider` 실제 구현. 웹은 기존 모의 구현 유지
- 광고 단위 ID는 **코드에 직접 쓰지 않고 환경 설정 파일**에 두고, 개발·내부 테스트는 테스트 ID, 출시 빌드에서만 실제 ID로 교체

**규칙 (CLAUDE.md "절대 규칙")**
| 종류 | 위치·조건 |
| --- | --- |
| 전면 | 미션 완료 직후(완료 시트 전), 하루 최대 1번. `/pray` 진입 시 미리 불러오고 3초 안에 준비 안 되면 건너뜀 |
| 보상형 | 기록 화면 되살리기에서만. 끝까지 봐야(보상 지급 콜백) 되살아남 |
| 배너 | 기록 화면 하단에서만. 광고가 안 오면 자리를 접음(빈 공간 없음) |
| 금지 | 읽기·기도 중간에는 광고 없음 |

**구현 포인트**
- 네이티브 배너는 WebView 위에 겹쳐 그려지므로, 배너 높이만큼 기록 화면 하단 여백을 줘서 탭바·목록이 가려지지 않게 합니다.
- 비행기 모드에서는 광고를 건너뛰고 미션 완료는 정상 처리.
- **광고 콘텐츠 등급**: AdMob에서 가장 낮게(전체 이용가), 도박·데이트·주류 등 민감 카테고리 차단.
- **동의**: 유럽·영국에 배포하면 Google 동의 화면(UMP). iOS는 ATT 안내(iOS 출시 때).
- `app-ads.txt`를 `prore.co.kr` 루트에 업로드.
- 실제 광고를 개발 중에 직접 누르지 않습니다(계정 정지 위험).

**확인 기준** (spec T13)
- [ ] 전면 광고가 하루 1번만 (같은 날 두 번째 미션 불가라 날짜를 바꿔서 재확인)
- [ ] 보상형은 끝까지 봐야 되살아남, 중간에 닫으면 되살아나지 않음
- [ ] 배너가 기록 화면에서만 보이고 탭바를 가리지 않음
- [ ] 광고 로드 실패·비행기 모드에서 앱 흐름이 멈추지 않음

### 서버 스키마(`db/supabase/001_init.sql`) 보완 필요 사항
분석 중 찾은 문제입니다. **로그인·동기화를 시작하기 전에** 고쳐야 합니다(지금은 사용하지 않음).
1. 서버의 `set_updated_at` 트리거가 업서트할 때 기기가 보낸 `updated_at`을 `now()`로 덮어써서 "늦은 쪽 우선" 병합이 성립하지 않음
2. `keep_completed` 트리거가 예외를 던져 오래된 기기 행이 섞인 배치 전체가 실패 → 앱에서 먼저 병합하거나 전용 함수(RPC)로 처리
3. 포도원 만든 사람이 멤버에서 빠지면 주인 없는 포도원이 남음
4. 초대 코드가 16진수 6자리(약 1,600만 가지)이고 시도 횟수 제한이 없음
5. 나눈 열매의 기도 공개 여부를 나중에 바꿀 수 없음(수정 정책 없음)

## 7. 결정 기록

### 7.1 이미 정한 것
| 번호 | 결정 | 이유 |
| --- | --- | --- |
| D-01 | 기술 스택을 Vite에서 **Next.js 16 정적 export**로 변경 | 사용자 요청. 서버 기능은 쓰지 않아 Capacitor에 그대로 담김 |
| D-02 | 어제 읽기만 하고 못 끝낸 로그는 **이어서 완료 불가 = 놓친 날**, 오늘은 같은 장으로 새로 시작. 단 읽기→기도 흐름이 이어지는 동안(자정 넘김)은 시작 날짜 유지. 되살린 날의 책·장은 현재 진도(`next`) | 규칙을 "하루 1행, 자정에 닫힘"으로 단순화하고 되살리기와 일관 |
| D-08 | 읽던 스크롤 위치는 MVP에서 저장하지 않음 | DB에 칸이 없고 기능 최소화 원칙. 필요하면 002 마이그레이션 |
| D-12 | `sql.js`를 1.12.0에 고정 | jeep-sqlite가 포함한 JS와 wasm 버전이 맞아야 함(1.15는 LinkError) |
| D-13 | 나무 3그루 초과 시 최근 3그루만 그리고 나머지는 숫자 | spec "최대 3그루, 그 이상은 숫자로" |
| D-04 | 글꼴은 Pretendard 가변 1개 + 나눔명조 400·700 woff2만 번들(합계 6.2 MB). 서브셋은 하지 않음 | 용량이 성경 본문(8.7 MB)과 비슷해 감수 가능. 줄여야 하면 본문에 쓰인 글자만 남기는 서브셋을 추후 검토 |
| D-14 | 전역 상태의 쓰기는 한 줄로 처리 | 동시 실행 시 진도가 어긋나는 것을 실제로 재현해서 발견 |
| D-17 | 성경 절 번호는 **KJV 기준**(holybible 수집본). 약 100개 장에서 인쇄된 개역한글과 번호가 다름. 앱 정보에 안내 문구 | 대한성서공회 수집본은 시편 92편 누락·번호 이상으로 단독 사용 불가, 한·영 짝맞춤이 쉬움. **출시 후에는 구절 ID가 바뀌어 변경이 어려우므로 출시 전에 최종 확인** |
| D-18 | 개역한글 본문 교정은 뜻이 달라지는 3곳(민 18:11, 신 9:12, 사 48:13)만. 철자 차이 10곳은 원본 유지 후 검수 | 본문을 임의로 바꾸지 않는다는 원본 NOTICE 조건. 교정은 `KRV_FIXES`에만 기록 |
| D-19 | KJV는 영국 내에서 Crown copyright → 배포 국가에 영국을 넣을지 Play Console 설정 때 결정 | 원본 NOTICE |
